# dsh-limit-guard — сторож лимитов для DeepSeek Harness

Перед каждым шагом агента проверяет лимиты. Когда лимит близко, агент получает команду:
остановить новую работу, записать `.agent/handoff/STATUS.md` (цель, что сделано, что в процессе,
следующие шаги, файлы, время сброса лимита) и завершить ход. После этого сторож **держит стоп**:
автоматические шаги (раунды goal, продолжения хода) отклоняются, активный goal переводится в
`blocked` с кодом `usage-limit`, повторы упавших из-за лимита запросов не делаются. Продолжение —
вашим сообщением («продолжи по .agent/handoff/STATUS.md») или возобновлением goal после сброса.

Также добавляет инструмент `limit_status` — агент может сам посмотреть остаток, темп расхода
и сколько в среднем стоит задача.

## Страница «Настройки → Сторож лимитов»

- **Лимиты аккаунта** — по каждому окну (5h, 7d…): сколько осталось, сколько использовано, когда сброс,
  темп расхода (%/ч) и прогноз «кончится ~в 18:40» или «хватит до сброса», плюс «средняя задача ~4% →
  хватит примерно на N таких».
- **Предыдущая задача** — сколько % каждого окна она съела (было → стало), длительность, токены, итог.
  Задача = от вашего сообщения до момента, когда агент освободился (раунды goal входят в ту же задачу).
- **Текущие задачи** — что сейчас выполняется, «потрачено пока», режим сторожа по сессии и кнопка
  «Снять стоп».
- **История задач** и **события сторожа** (сворачивание, handoff записан, шаг отклонён, goal заблокирован…).
- Переключатели (сторож, блокировка goal, отключение бесполезных ретраев) и пороги. Изменения
  сохраняются в `~/.dsh/limit-guard/state.json` и действуют сразу; «По умолчанию» возвращает значения
  из `cordis.patch.yml`.

«Потрачено» меряется по общему аккаунту: если параллельно работают две сессии, дельта у них общая.
Точность — как у источника (Wiolett/Codex отдают проценты, опрос раз в минуту и принудительно в начале
и конце задачи).

## Как работает стоп (режимы сессии)

| Режим | Когда | Что делает сторож |
|---|---|---|
| норма | лимит ниже `warnPercent` | ничего |
| пишет handoff | автоматический шаг пересёк `warnPercent` | одно уведомление «сворачивайся», goal → blocked; даётся `handoffSteps` шагов после записи STATUS.md (или `graceSteps` максимум) |
| остановлена | бюджет шагов исчерпан / лимит кончился | раунды goal и пустые продолжения отклоняются; входящее сообщение субагента/напоминание — одно короткое «прими к сведению» |
| продолжает по вашему слову | вы написали сообщение выше порога или возобновили goal | короткая пометка «осталось ~N%», работа идёт до `hardStopPercent`, там — повторное сворачивание |

Ваши сообщения не отклоняются никогда. Если лимит ≥ `hardStopPercent`, агент на ваше сообщение
коротко отвечает, сколько осталось и когда сброс, и не начинает длинную работу (или выключите сторож
в настройках). Стоп снимается сам, когда окно сбросилось (лимит ниже `warnPercent`).

## Кнопка «Саммари для следующих чатов»

В чатах, где уже был хотя бы один ход, рядом с кнопкой отправки появляется иконка документа со стрелкой.
Нажатие отправляет агенту запрос: остановиться, записать `.agent/handoff/STATUS.md` (цель, сделано, в процессе,
следующие шаги, файлы, решения, вопросы, лимиты) и ответить коротким саммари. Если в поле ввода уже есть текст,
он добавляется к запросу как дополнительная заметка. Пока агент занят, запрос встаёт в очередь (как обычное сообщение).

## Источники

| Источник | Для кого | Откуда |
|---|---|---|
| Контекст сессии | все | встроенный счётчик токенов DSH |
| Wiolett | провайдер `opfield` | `GET https://ops.wiolett.net/api/inference/v1/usage`, ключ `OPFIELD_API_KEY` |
| ChatGPT / Codex | провайдер `openai-codex` | `chatgpt.com/backend-api/wham/usage`, вход из плагина `dsh-openai-codex-auth` |

Лимиты аккаунта проверяются только для агентов, чья модель идёт через соответствующего провайдера.
Источник без учётных данных просто пропускается (на странице — «недоступен»). Наружу уходят только
проценты и время сброса.

## Установка / обновление

1. Скачать репозиторий (`git clone https://github.com/IsselSaizo/NeuroPlugins.git`) или только папку
   `dsh-limit-guard` и положить её куда угодно (например `D:\dsh-plugins\dsh-limit-guard`).
2. В DSH попросить агента: «установи бандл из папки D:\dsh-plugins\dsh-limit-guard»
   (он вызовет `plugin_manager install_bundle`), либо через Settings → Plugins.
3. **Перезапустить DSH** (Host-часть грузится при старте), затем обновить страницу (Ctrl+R).
4. Открыть Настройки → «Сторож лимитов» или спросить агента «покажи limit_status».

Для ChatGPT Plus: должен быть установлен и залогинен `dsh-openai-codex-auth` (Settings → OpenAI Codex).

## Настройки (`cordis.patch.yml`)

| Поле | По умолчанию | Смысл |
|---|---|---|
| `enabled` | true | главный выключатель (учёт задач работает и при выключенном) |
| `warnPercent` | 90 | % использования окна аккаунта → сворачивание и handoff |
| `contextWarnPercent` | 85 | % заполнения контекста → handoff и совет начать новую сессию |
| `hardStopPercent` | 98 | порог повторного сворачивания, если вы продолжили выше `warnPercent` (101 = никогда) |
| `graceSteps` | 8 | максимум шагов на handoff, потом автоматические шаги отклоняются |
| `handoffSteps` | 2 | сколько шагов дать после записи STATUS.md (на итоговое сообщение) |
| `blockGoals` | true | переводить активный goal в `blocked` (`usage-limit`) |
| `stopRetryOnQuota` | true | не повторять запрос, упавший на исчерпанном лимите (`QUOTA`, или `RATE_LIMIT` при окне ≥99.5%) |
| `historySize` | 60 | сколько завершённых задач хранить |
| `cacheMs` | 60000 | как часто опрашивать лимиты |
| `handoffPath` | `.agent/handoff/STATUS.md` | путь относительно рабочей папки сессии |
| `stateFile` | `~/.dsh/limit-guard/state.json` | где хранить историю и настройки со страницы |
| `wiolett.*`, `codex.*` | см. патч | `enabled`, `url`, `credential`, `providers` |

Чтобы поменять в патче, переопределите строку `limit-guard` в своём профильном патче целиком
(`config` заменяется, а не сливается). Проще — со страницы настроек.

## HTTP API (для страницы)

`GET /limit-guard/api/dashboard[?refresh=1]`, `POST /limit-guard/api/settings {key,value}|{reset:true}`,
`POST /limit-guard/api/clear-history`, `POST /limit-guard/api/release {sessionId}`. POST принимает только
`application/json`. В дашборде есть первые ~140 символов ваших запросов — если DSH слушает не loopback-адрес,
учитывайте, что маршрут без авторизации (как и у Token Saver).

## Ограничения

- Endpoint'ы Wiolett и ChatGPT не документированы и могут измениться; при ошибке источник
  показывается как `unavailable`, работа агента не блокируется.
- Если Codex-токен истёк, он обновится при следующем запросе к модели; до этого источник недоступен.
- Субагенты получают короткую версию: закончить текущую правку и отчитаться родителю.
- Факт записи handoff определяется по вызову инструмента, в аргументах которого есть путь `handoffPath`.
  Если агент пишет файл иначе, работает ограничение `graceSteps`.
- Режимы сессий хранятся в памяти: после перезапуска DSH стоп снимается (goal при этом остаётся blocked).
